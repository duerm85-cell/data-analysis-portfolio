# A 股量化数据工程平台：面试作品集说明

> 最后核对：2026-09-01。本文用于你自己准备面试、向招聘方发送链接，以及向面试官解释项目结构。

## 先说结论：现在能不能用于面试？

**可以。** 这个项目已经不是“只有一个网页界面”的作业，而是一套可讲清楚的数据工程与数据分析作品集：有数据接入、分层清洗、质量校验、因子加工、SQLite 服务层、可视化、模型评估、回测、测试与公开部署方案。

但要诚实地定位它：

- 它最适合投递 **数据分析、数据开发、量化数据开发** 的初级/校招岗位。
- 它不是“可以实盘赚钱的量化策略”。本地回测结果明确显示当前技术因子信号较弱、未跑赢同期沪深 300；这是项目的可信点，而不是缺点。
- 公开网站使用的是**固定随机种子的合成演示行情**，不是重新发布 Tushare/AKShare 真实逐日行情；真实数据、Token、模型权重和用户库不上传 GitHub。

### 线上访问的当前注意事项

应用代码中**没有强制用户登录**：公开模式默认就是访客只读访问，账户功能只有在设置 `QUANT_REQUIRE_LOGIN=1` 时才启用。

不过，Streamlit 的“是否公开”是平台设置，不是代码设置。你已在分享面板看到 `Make this app public` 是蓝色，但仍应做一次最终验收：用手机流量、浏览器无痕窗口，或请没有登录 Streamlit 的朋友打开在线演示链接。只要能直接进入系统，就可以放心放入简历；如果跳到 Streamlit 登录页，进入 Streamlit 的 `Manage app → Settings → Sharing`，确认查看权限为 `This app is public and searchable` 后保存。

## 面试官一般会怎么查看？

常见流程是：

1. HR 或业务面试官先点在线演示，花 30 秒看首页、市场概览和图表是否专业。
2. 技术面试官打开 GitHub README，确认你写了什么、数据是否真实、项目能否运行。
3. 他们会挑一两个问题追问，例如“数据怎么来的”“为什么数据质量页有缺失”“模型效果如何”“如何避免未来函数”“为什么要 SQLite”。
4. 比较认真时会点开 `app_pro.py`、`data_preprocessing.py`、`data_quality.py`、`model_training.py`、`backtest.py`，看模块划分、异常处理和测试。

因此你不需要让对方逐行看完代码。你的目标是让他在 2 分钟内看到完整性，在 10 分钟内相信你确实理解数据链路和结论边界。

## 你可以怎样介绍项目（60 秒版本）

> 这是我从本科项目继续工程化的 A 股量化数据平台。主链路是把 Tushare 行情写入原始层，经过标准化清洗、质量校验和技术/情绪因子加工后，同步到 SQLite 给 Streamlit 看板使用；训练和回测严格按时间切分，T 日信号对应 T+1 收益并计入手续费。公开部署版使用合成行情和脱敏研究摘要，避免重新分发数据源行情与模型文件。我的重点不是包装策略收益，而是把数据血缘、质量规则、模型验证、回测成本和网页展示做成一条可复现的链路。

### 2. 数据采集与清洗

| 文件 | 做什么 | 关键价值 |
|---|---|---|
| `fetch_stock_data.py` | 使用 Tushare 获取股票列表、逐股日线和沪深 300 基准，并写入 `data/raw/` | 把数据源与后续加工分开；Token 从环境变量读取，不写入代码 |
| `scripts/update_market_data_akshare.py` | 无 Tushare Token 时，以 AKShare/Sina 做增量更新；对重叠日期做价格、成交量、成交额校验 | 展示备用数据源、增量更新、重试和跨源口径校验能力 |
| `fetch_sentiment.py` | 可显式选择真实情绪抓取或生成演示情绪；文本转情绪分数并可合并因子 | 网络失败不偷偷制造随机“真实数据”；演示模式必须明确指定 |

### 3. 因子、数据库和大数据链路

| 文件 | 做什么 | 关键价值 |
|---|---|---|
| `factor_engineering.py` | 基础技术因子计算入口 | 保留不含情绪的技术因子加工链路 |
| `factor_engineering_with_sentiment.py` | 计算 MA、RSI、MACD、波动率、收益标签等技术因子；合并情绪因子；输出 Parquet 并同步 SQLite | 是 DWS 因子宽表的主实现，供模型、回测和看板共同使用 |
| `database_manager.py` | `StockDatabase` 封装 SQLite 表创建、唯一索引、动态安全建列、分块 upsert、参数化查询、事务回滚 | SQLite 是本项目的 Serving/ADS 层：比每次从 CSV 扫描更适合交互网页 |
| `scripts/rebuild_serving_database.py` | 从加工后的数据校验、备份并原子重建 SQLite | 防止旧库字段不完整或半写入状态直接影响网页 |
| `spark_pipeline.py` | 可选 PySpark 链路：建 Spark Session、清洗、窗口函数计算因子、按年份写 Parquet | 说明你理解从 Pandas 单机处理向大数据批处理演进，但没有虚构未落地的组件 |
| `sql/analytics_queries.sql` | SQL 示例：数据覆盖、新鲜度、按股票查询、数据质量、板块宽度 | 展示指标口径和参数化查询意识 |

### 4. 建模和回测

| 文件 | 做什么 | 面试时应强调什么 |
|---|---|---|
| `model_training.py` | `OptimizedStockPredictor` 负责特征选择、时间序列滚动验证的 XGBoost、按 70/15/15 时间切分并早停的 BiLSTM、评估日志写入 | 不随机打乱时间序列；验证集和测试集有职责边界，防止未来数据泄漏 |
| `backtest.py` | `StockBacktester` 使用 T 日信号对应 T+1 收益，计算换手、佣金、印花税、净值、回撤和基准比较 | 明确交易成本和基准来源；不把股票池等权收益偷换成沪深 300 |
| `results_optimized/README.md` | 说明模型权重、预测明细和评估产物是本地生成且不提交 | 公开网站不提供权重，避免云端大依赖与研究资产泄露 |
| `backtest_results/README.md` | 说明指标、净值和逐日持仓为本地生成物 | 公开网站只给脱敏指标与归一化曲线 |

你应该主动说的研究结论：当前技术因子模型只有很弱的统计信号，XGBoost 样本外 AUC 约 0.5204；含成本策略未跑赢同期沪深 300。这个结论说明你不会为了展示效果而挑选或粉饰结果。

## 最容易被问到的问题与回答方向

### “这是真实数据吗？”

本地研究链路可以接 Tushare，历史数据也做过本地验收；但公开网站为了遵守数据源再分发限制，使用固定随机种子生成的合成演示行情。页面明确标示“合成演示、非实时、非投资建议”，而模型和回测只展示脱敏研究摘要。这样既可以让面试官体验系统，也不把第三方逐日行情和凭证上传。

### “为什么有缺失值？你的数据不是已经清洗了吗？”

清洗不等于把所有空值都随意填掉。项目把缺失分成结构性缺失与未预期缺失，质量页会显示字段级详情。对会影响模型或行情合法性的缺失会过滤/阻断；对某些在特定窗口天然无法计算的指标，保留其含义并透明展示。重复主键和非法 OHLC 是 0，但缺失仍必须被治理和说明。

### “模型准确率只有 52%，为什么还放项目里？”

金融日频方向预测的信号普遍弱。重点是我采用时间序列验证、防止泄漏，并且将弱信号和未跑赢基准的结果如实呈现。相比为了演示而给出不可信的高收益，我更关注数据和研究结论能被复现、审查。

### “SQLite 为什么够用？”

它适合作品集和单机分析型服务层：部署简单、零运维、支持索引与参数化查询。项目中用 `(code, date)` 唯一索引、分块 upsert 和事务处理。若扩展到分钟/Tick 级数据或高并发查询，可迁移到 ClickHouse、Doris 或云数仓。

### “怎么避免未来函数？”

训练与验证按时间切分；XGBoost 使用滚动验证，BiLSTM 按 70/15/15 的时间顺序拆分；回测采用 T 日信号对应 T+1 收益。也就是说，T 日收盘后才能形成的信号不会拿去赚 T 日自己的收益。

### “项目里为什么还有登录代码？”

它是本地演示功能，用于体现账户表、密码哈希和会话处理；公开作品集默认关闭，访客只读浏览。真正网站的访问控制由 Streamlit Cloud 分享设置管理，不把用户数据上传到 GitHub。
