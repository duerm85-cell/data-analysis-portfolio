# 阶段2数据规模与性能优化报告

## 验收结论

公开 Demo 已从“50只股票的整表展示”升级为三层数据产品：

- 资产目录层：5,200只确定性合成资产元数据；
- 分析汇总层：5,200只资产口径的3年市场/行业日聚合，共31个行业、756个交易日；
- 交互明细层：300只行业×板块分层样本，每只252个交易日，共75,600行。

扩容后五类核心 SQLite 查询的本地暖查询中位数均低于7 ms，明显低于项目设定的500 ms验收线。

## 测试口径

- 阶段1前：旧版 Streamlit 启动时整表读取 Parquet，37,800行×48列，137.163 ms，DataFrame 深度内存15,271,332字节。
- 阶段1后：Git提交 `13b6961` 保留的7轮 SQLite 基准结果，当时为50只公开明细。
- 阶段2后：扩容后服务库连续执行15轮，报告使用中位数；原始结果见 `benchmark_results.json`。
- 测试环境：同一台 Windows 开发机、SQLite只读连接。绝对耗时会随硬件和系统负载波动，不代表 Streamlit Cloud 网络耗时。

## 三阶段对比

| 测试项 | 阶段1前 | 阶段1后 | 阶段2后 | 阶段2返回行数 |
|---|---:|---:|---:|---:|
| 启动整表 / 资产目录 | 137.163 ms（整表） | 1.1360 ms | 0.8469 ms | 300 |
| 单股近252日 | 需先加载整表 | 2.9885 ms | 0.9287 ms | 252 |
| 单股3年条件查询 | 需先加载整表 | 8.0554 ms（756行） | 0.9750 ms（公开库1年，252行） | 252 |
| 某日市场快照 | 需先加载整表 | 2.4992 ms（50行） | 6.1737 ms（300行） | 300 |
| 单行业3年趋势 | 需先加载整表 | 5.1170 ms | 2.0926 ms | 756 |

阶段2的市场快照返回行数扩大6倍，耗时约2.47倍，单行成本反而下降约59%。最慢的查询仍只有6.17 ms，相比旧整表读取的137.16 ms约快22.2倍。

## 查询计划与产品验收

- 单股查询命中 `PRIMARY KEY(code, date)`。
- 市场快照命中 `idx_stock_daily_date(date)`。
- 行业趋势命中 `PRIMARY KEY(industry_l1, date)`。
- 10个 Streamlit 页面全部通过 AppTest 冒烟测试；股票画像和行业分析页本地测试运行分别约1.92秒和1.55秒。
- SQLite `integrity_check=ok`，外键异常0；库文件47,886,336字节，低于 GitHub 单文件100 MB限制。

## 解读边界

阶段2故意不为300只公开标的保存3年宽表：交互明细只保留1年，市场和行业趋势使用3年预聚合。这是用约48 MB的可部署文件换取更大目录和交互覆盖，不把没有在线明细的数据宣传为可查明细。
